## 1. What we're building

Exam results that **can't crash on results day**.

Every year results sites go down the moment results are announced. ZeroHour borrows how Steam launches games: the content is delivered early in encrypted form, and at launch time only a tiny key is released.

- Days before results day, every student's result is encrypted and pushed to **CloudFront**. Students can pre-fetch their own encrypted file to their phone.
- At release time the only thing anyone downloads is a **32-byte key** (`release.json`). Decryption happens in the browser.
- Release requires **2 of 3 officials** to approve from their phones.
- Results are stored with **S3 Object Lock**, so marks can't be quietly changed after publishing.

## 2. Demo moment (design around this)

## 3. Architecture

```
Admin CSV ──► S3 raw/ (private, KMS)
                │
                ▼
  Step Functions (Standard) ── Distributed Map (ItemReader: S3 CSV)
                │                  └─ Lambda "encryptBatch" (per batch of rows)
                ▼
  S3 public/r/<sha256(USN)>.bin  (Object Lock, GOVERNANCE mode)
  S3 public/manifest.json (SHA-256 of every file)
                │
                ▼
  CloudFront (long TTL on r/*, short TTL on release.json)
                ▲
  PWA (S3 + CloudFront): pre-fetch encrypted file → IndexedDB → poll release.json → WebCrypto decrypt

Release:
  Lambda durable function "releaseWaiter": waits until releaseAt (paused, no compute billed)
     └─► starts Step Functions "approvalFlow"
            └─ Task with waitForTaskToken; Lambda "approve" (API Gateway) records approvals
               in DynamoDB with conditional updates; at 2 of 3 it calls SendTaskSuccess
     └─► Lambda "publishKey": writes release.json {released:true, key}, invalidates /release.json
```

Fallback if durable functions give trouble: EventBridge Scheduler one-time schedule at `releaseAt` → same approval flow. Keep durable functions as the headline if they work.

## 4. Crypto design

- One random 256-bit **master key** per results batch, generated by KMS `GenerateDataKey`. Store only the **encrypted** form (DynamoDB `batches` table). `encryptBatch` Lambdas decrypt it via KMS.
- Per-student key = **HKDF-SHA256**(master key, salt = per-file random 16 bytes, info = `USN || DOB`).
- Encrypt the student's JSON with **AES-256-GCM**. File = `salt | iv | ciphertext | tag`.
- File name = hex SHA-256 of normalised USN (no USN in paths).
- At release, `release.json` = `{ released: true, batchId, key: base64(masterKey), releasedAt }`. Browser derives the per-student key from USN + DOB and decrypts with WebCrypto.
- Before release, `release.json` = `{ released: false, releaseAt }`.
- Same security model as today's portals after release (USN + DOB), but **nobody can read anything before release**.

(Exact byte layout, normalisation and padding are pinned down in `docs/M1-PLAN.md`.)

## 5. Components

- **Admin page** (static, Cognito-protected or a simple signed-URL upload): upload CSV, set `releaseAt`, add 3 approver contacts, start publish.
- **Publish workflow:** Step Functions Distributed Map over the CSV in S3; batch size ~500 rows; writes encrypted files + manifest.
- **Student PWA:** enter USN + DOB once → service worker pre-fetches the encrypted file into IndexedDB → countdown → auto-decrypt at release. Works offline after pre-fetch except for the tiny key.
- **Approver page:** mobile page showing batch info + Approve button (signed one-time links via API Gateway + Lambda).
- **Live dashboard:** staged count, approvals (0/3 → 2/3), release state, CloudWatch latency + request graphs, cost estimate.
- **Integrity:** S3 Object Lock **GOVERNANCE mode, 1-day retention** (not COMPLIANCE — compliance mode can't be undone and would block cleanup). Manifest hashes shown on the dashboard.

## 7. Infrastructure

- **AWS SAM** (or CDK in TypeScript if preferred) — one `template.yaml`, deploy with `sam deploy --guided`.
- Region **ap-south-1 (Mumbai)**; confirm Lambda durable functions are available there before starting.
- Runtime Node.js 22 (TypeScript, esbuild bundling).
- DynamoDB tables: `batches`, `approvals`. KMS key for the master key. Two S3 buckets (raw private; public behind CloudFront OAC).
- No servers, no containers, no CI pipeline required.

- Pre-release request for `release.json` returns `released:false`.
- Manifest hash check for a sample of files.
